# Guion L02 — Orquestar ALM con Claude Code y GitLab (60 min)

## Propósito
Separar **GitHub documental**, **GitLab del equipo**, **Claude Code como motor**, **contrato de fase**, **metaprompt**, **prompt operativo** y **evidencia**. Esta distinción sostiene el resto del taller.

## Minutaje
- 00–10: diagrama de tres sistemas y comparación pipeline ALM / pipeline CI.
- 10–20: demostrar la estructura de la plantilla.
- 20–35: alumnos clonan, abren Claude Code y localizan contratos.
- 35–50: ejecución del primer metaprompt en modo «solo prompt».
- 50–60: revisión del prompt operativo y gate humano.

## Explicación recomendada
«Este GitHub no es donde cada equipo crea la aplicación. Aquí estudiamos. En GitLab están nuestras issues, ramas, código y CI. Claude Code actúa sobre el clon. No existe un botón de GitLab que haga aparecer por sí solo la especificación de la empresa». Ilustra en pizarra **metaprompt → prompt operativo → artefacto → prueba → aprobación**. Insiste en que el primer paso produce *un prompt*, no el software.

## Demostración práctica
Abre **03_GITLAB_PLANTILLA/CLAUDE.md**, **alm/maestro.md** y un contrato. Muestra las rutas obligatorias y el doble gate. Genera el prompt de requisitos, inspecciona sus secciones y detente. Debes demostrar deliberadamente que **todavía no existe la especificación final**, para evitar confusión de niveles.

## Puntos de observación
Un alumno puede ejecutar Claude fuera del directorio y el agente no encontrar CLAUDE.md. Indícale el directorio y vuelve a leer el contrato. Otro puede intentar escribir una API desde el metaprompt; exige que se detenga y entregue solo el prompt. Si faltan credenciales GitLab, practica la preparación local y registra el bloqueo; no inventes la conexión.

## Preguntas con respuesta
**¿Cuál es el valor añadido del contrato?** Define expectativas y comprobaciones independientemente del modelo. **¿Por qué dos gates?** Se aprueban intención y resultado. **¿GitLab CI ejecuta el pipeline ALM?** No, ejecuta sus jobs; el protocolo ALM aquí lo dirige Claude en el entorno de trabajo.

## Gate
Cada alumno identifica en pantalla los tres archivos de orquestación, el prompt generado, las entradas y el criterio de aprobación. No avanzar si creen que el documento generado ya equivale a ejecución.
