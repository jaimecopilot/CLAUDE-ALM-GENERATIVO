# Guion L02 — Cuenta GitLab propia y preparación de dos ejecuciones (90 min)

## Propósito
Cada alumno deberá tener cuenta GitLab propia (existente o nueva), **proyecto personal privado** y copia de la plantilla, antes de pedir a Claude que produzca un solo documento de requisitos. Se prepara la doble modalidad: manual en \`practica/manual\` y automática en otra rama desde \`base-alm\`.

## Minutaje
- 00–15: explicar cuenta, proyecto, repositorio, namespace, rama y tag.
- 15–35: acompañar login/registro y creación de proyecto GitLab personal.
- 35–60: instalación/comprobación de herramientas, clonado y copia de plantilla.
- 60–75: primer commit, push a main, tag \`base-alm\`, rama manual.
- 75–85: verificar issues, MR, permisos y runners.
- 85–90: gate y demostración de contratos/metaprompts.

## Demostración
Muestra en directo GitLab.com → Create new → New project/repository → Create blank project. Elige namespace de tu usuario, nombre \`coworking-alm-junior\`, visibilidad Private y **sin inicializar README**. Muestra que GitLab almacena código, issues y CI; no es el motor de generación de texto.

Clona el curso y un proyecto GitLab vacío, copia solo \`03_GITLAB_PLANTILLA\` con PowerShell \`Get-ChildItem -Force | Copy-Item -Recurse -Force\`, haz primer commit y etiqueta \`base-alm\`. Explica por qué el tag no debe apuntar al código generado en L05.

## Errores comunes
- El alumno crea el proyecto en un grupo ajeno en vez de su namespace personal.
- Selecciona Public y expone resultados o credenciales: corregir a Private.
- Marca Initialize with README y encuentra conflicto al importar: resolver el primer commit sin forzar historial.
- No copia archivos ocultos (especialmente .gitignore y .gitlab): copiar con \`-Force\`.
- Ejecuta Claude desde la carpeta del **curso docente** en lugar del clon GitLab: corregir directorio.
- Lanza automatización sin guardar \`base-alm\`: recuperar el estado inicial antes de seguir.

## Preguntas de evaluación
**¿El profesor debe entregar una URL de proyecto?** No: cada alumno crea la suya. **¿Para qué sirve el tag base-alm?** Para repetir el ALM desde la misma plantilla sin aprovechar código manual. **¿Por qué son dos pipelines distintos?** El ALM produce artefactos y GitLab CI verifica código/entrega.

## Gate
URL de proyecto privado, plantilla importada, etiqueta base, rama manual, autenticación personal Claude Code y estado de runners comprobado. En L03 comienza el trabajo generativo.
