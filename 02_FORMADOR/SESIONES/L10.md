# Guion L10 — GitLab orquesta el ALM generativo (180 minutos)

## Tesis que demostrar
**Claude genera el pipeline; GitLab lo ejecuta; Claude genera artefactos dentro de los jobs; el alumno revisa resultados.** El otro recorrido del curso es fase a fase mediante Claude Code.

## Minutaje
- 00–20: arquitectura de dos modos y dos tipos de pipeline.
- 20–40: preparar rama desde base-alm y confirmar presupuesto API.
- 40–85: Claude genera YAML de seis jobs y scripts de apoyo.
- 85–110: revisión de variables, permisos, dependencias y artefactos.
- 110–160: GitLab ejecuta, cuando exista API autorizada, y se inspeccionan jobs.
- 160–180: comparar manual/automático y señalar límites.

## Corrección de la confusión
No es un orquestador local de Python. Los jobs se ejecutan en GitLab Runner. Si se genera un script de soporte, debe ejecutarse **dentro de un job**. La configuración `.gitlab-ci.yml` inicial se crea guiada con Claude, porque GitLab no puede iniciar un pipeline inexistente.

## Traspaso de datos
Se necesita `artifacts` y dependencia `needs` o descarga equivalente. Ejemplo: `alm_desarrollo` requiere requisitos y arquitectura generados por `alm_requisitos` y `alm_diseno`; no recibe documentos prefabricados ni escribe nuevos requisitos desconectados.

## Presupuesto y seguridad
API de Anthropic facturada por tokens más minutos GitLab Runner. Una cuenta Pro local no habilita gratuitamente esta integración. No compartir claves del formador en proyectos que administren alumnos. Poner límites de gasto, tiempo y concurrencia; usar variables de CI enmascaradas y disparo manual.

## Demostración y validación
En GitLab mostrar cada job, log y artefactos concretos; las pruebas que fallan bloquean. Si no hay credenciales, se explica la arquitectura pero no se afirma ejecución real. Comparar con la rama manual y evaluar el conocimiento de gates, trazabilidad y diferencias del producto.

## Preguntas finales
¿Quién crea el YAML? Claude con revisión humana. ¿Quién lo ejecuta? GitLab. ¿Quién ejecuta IA durante cada fase? Claude en jobs del runner. ¿Por qué necesitan artifacts? Cada job es aislado. ¿Por qué Pro no basta? Porque el runner usa API facturada o proveedor autorizado.
