# Guion L09 — Documentación y trazabilidad (60 min)

## Competencia
Demostrar que una persona ajena al equipo puede seguir la historia de una funcionalidad desde una necesidad de negocio hasta código, prueba y entrega. Referencias: P2.6, P8.8 y T8.4 originales.

## Minutaje
- 00–15: teoría de trazabilidad bidireccional y documentación as-built.
- 15–25: generar prompt operativo de documentación.
- 25–40: Claude produce README y matriz.
- 40–50: cotejar diagramas con código real.
- 50–60: ejercicio de lectura cruzada y gate.

## Demostración
Elige RF-03. Sigue: especificación → CA de solapamiento → issue → archivo servicio → test → MR → pipeline. Si falta un elemento, escríbelo como pendiente con razón. Muestra una discrepancia común: Mermaid dice que hay un servicio independiente, pero todo está en un endpoint. El equipo debe decidir si corrige diseño documentado o refactoriza, sin falsificar historia.

## Errores típicos
Enlaces a issues ficticias, README que describe comandos inexistentes, informes de cobertura estimados y diagrama arquitectónico que representa una versión anterior. Corrige contra archivos reales, no pidiendo «hazlo más bonito».

## Preguntas
¿La trazabilidad es una tabla decorativa? No, permite demostrar origen y aceptación de cambios. ¿Puede Claude escribir documentación? Sí, pero un humano verifica coincidencia con código. ¿Debe guardarse el chat entero? No es requisito; la evidencia útil son prompts aprobados, archivos, pruebas y decisiones.

## Gate
Una fila completa y verificable de RF-03 y otra de CAM-01, README que permite ejecutar y limitaciones conocidas consignadas.
